# TensorFlow Lite Micro Setup for ESP32

The neural-network experiments that export `.tflite` models need a TensorFlow Lite Micro runtime on the target board. TinyML-Lab uses **Chirale TensorFlowLite** as the reference Arduino package for the current ESP32 compile checks.

## Reference library

Repository: `spaziochirale/Chirale_TensorFlowLite`

The library is an Arduino-oriented TensorFlow Lite Micro package and declares support for ESP32 architectures. It is distributed under the Apache License 2.0. TinyML-Lab does not vendor or relicense this library; it is installed as an external dependency during the compile workflow.

## Arduino installation

For a local Arduino CLI installation, clone the library into the Arduino libraries directory:

```bash
mkdir -p ~/Arduino/libraries
git clone --depth 1 https://github.com/spaziochirale/Chirale_TensorFlowLite.git \
  ~/Arduino/libraries/Chirale_TensorFlowLite
```

The sketches use the current umbrella header:

```cpp
#include <Chirale_TensorFlowLite.h>
```

and the TensorFlow Lite Micro headers required by the interpreter:

```cpp
#include "tensorflow/lite/micro/all_ops_resolver.h"
#include "tensorflow/lite/micro/micro_interpreter.h"
#include "tensorflow/lite/schema/schema_generated.h"
```

## Generate the model header first

Model arrays are generated by the corresponding Python training script and are intentionally not treated as hand-maintained source files. For example:

```bash
python 13-cnn/train.py
```

creates the model header used by the CNN Arduino sketch. The same pattern is used for the other TensorFlow/TFLite experiments.

## ESP32 compile flow

The automated workflow performs the following sequence:

1. install the Python/TensorFlow dependencies;
2. run the TensorFlow experiment scripts and generate their model headers;
3. install Arduino CLI and the Espressif ESP32 core;
4. install Chirale TensorFlowLite as an external Arduino library;
5. compile each TensorFlow-family sketch against the generic ESP32 target.

The corresponding automation is `.github/workflows/tflm-esp32-compile.yml`.

## Runtime notes

Tensor arenas in the examples are intentionally conservative starting values. A successful compilation does not prove that the chosen arena is optimal or that enough runtime memory is available under every application configuration. Arena size should be measured and reduced only after the model has been tested on the intended physical board.

Likewise, a successful board compilation is separate from physical-device validation. Flash usage, RAM usage, inference latency and desktop-to-device prediction agreement should be recorded from the actual target before those values are reported as measured results.
